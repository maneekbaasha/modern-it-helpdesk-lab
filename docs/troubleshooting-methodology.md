# IT Troubleshooting Methodology

This lab uses a simple troubleshooting workflow designed for IT Helpdesk environments.

## 1. Understand the symptoms

Let the user describe what is happening.

Identify:
- what is not working
- when the issue started
- error messages or unusual behavior

## 2. Determine the scope

Ask whether the issue affects:
- one application
- one device
- one user
- multiple users
- the entire organization

Scope helps determine both the technical direction and the impact of the incident.

## 3. Identify recent changes

Look for changes such as:
- password changes
- software installations
- updates
- configuration changes
- new hardware
- network changes

## 4. Form a hypothesis

Use the collected evidence to identify the most likely cause.

Do not change several things at once.

## 5. Test the hypothesis

Perform the least disruptive test possible.

A good test should either strengthen or weaken your hypothesis.

## 6. Apply the fix

Once enough evidence exists, perform the smallest appropriate corrective action.

Avoid unnecessary resets, deletions or configuration changes.

## 7. Validate

Never assume the incident is resolved.

Ask the user to reproduce the original action and verify that the service works normally.

## 8. Document

Record:
- symptoms
- diagnosis
- actions
- result

A useful Helpdesk ticket should allow another technician to understand what happened without repeating the investigation.

## Core principle

**Symptoms → Scope → Recent changes → Hypothesis → Test → Fix → Validation → Documentation**
