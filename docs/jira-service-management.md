# Jira Service Management Fundamentals

Jira Service Management is used in this lab to simulate an IT Helpdesk ticketing environment.

## User portal

The portal represents the employee-facing side of the Helpdesk.

Users can submit requests such as:
- technical incidents
- access problems
- application issues
- hardware requests

## Agent view

The agent view is used by IT Support technicians to:
- review tickets
- qualify incidents
- assign requests
- investigate problems
- communicate with users
- document technical actions
- resolve tickets

## Incident lifecycle

A simplified lifecycle used in this lab is:

**Reported → Qualified → Investigated → Remediated → Validated → Documented → Resolved**

## Impact

Impact describes how broadly the issue affects the organization.

Example:

A single employee unable to use Outlook may have a localized impact.

An email outage affecting the entire company would have a much larger impact.

## Urgency

Urgency describes how quickly the incident needs attention.

A problem preventing an employee from performing an important task can have high urgency even when only one person is affected.

## Priority

Priority can be determined from a combination of impact and urgency.

The exact priority matrix may vary between organizations.

## Internal notes

Internal notes are intended for the support team.

They should contain useful technical information such as:
- observations
- diagnosis
- troubleshooting performed
- remediation
- validation results

## Customer responses

Customer responses should remain clear and concise.

Avoid unnecessary technical details unless they are useful to the user.

The technician should confirm that the issue is resolved before closing the ticket.
